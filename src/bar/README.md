# bar/ — 语音条 UI

**空目录不是遗漏，是本轮明确划出去的范围。**

语音输入不属于 observe → judge → act → verify 四步中的任何一步，它是第五件事：
输入通道。Phase 1 的输入通道是命令行文本（`bright-sight run "..."`），理由有两条：

1. 命令行文本自带标点，中文切片器的可靠性远高于无标点的语音转写。先在可靠输入上
   把闭环的判据钉死，再去接不可靠输入，出问题时才分得清是切片器不行还是转写不行。
2. 闭环的正确性判据（逐字校验、三道硬闸、返回值 + 快照 diff）与输入从哪来无关。
   先做语音只会让这些判据在一个更吵的环境里被验证。

归属阶段：Phase 2，与 `is_command` 判断、`source: "voice"` 一起做——
那个判断在命令行下结构性恒为真，只有接了语音才有意义。
