# 设计：安全边界

这个项目能做的事只有两件：开标签页、建笔记。这份文档讲的是怎么保证它只做这两件。

读代码之前先读这里。`src/osa.ts`、`src/scripts.ts`、`src/policy.ts` 是安全核心，刻意保持为独立文件，藏进 `execute.ts` 就没有单一可审计对象了。

## 一、标识符与值两层分离

|  | 来源 | 可否拼进脚本文本 | 校验 |
|---|---|---|---|
| **标识符** | sdef（磁盘上的系统文件）、代码常量 | 可以 | 须过字符集白名单 |
| **值** | 用户原话、模型输出、页面回读、剪贴板 | **永远不可以** | 只走 `argv` |

AppleScript 的 `note`、`body`、`window` 是关键字不是字符串，无法经 argv 传递。这是客观限制，所以标识符必须允许插值。但标识符只来自 sdef 和代码常量，不受用户输入与模型输出影响，字符集校验是纵深防御。

值这一侧零例外：`execFile`（无 shell）加 `on run argv`（值不进字符串字面量），两层「无需转义」叠加，转义需求归零。`src/osa.ts` 是唯一 spawn `osascript` 的出口。

`test/osa.test.ts` 喂 `"`、`\`、换行、emoji 以及 shell 注入样本，断言逐字节原样返回，一次性证明 argv 不变式。

## 二、五态策略

`src/policy.ts` 把一个带概率的判断收敛成五种结论之一：

`execute` / `confirm` / `ask` / `wait` / `ignore`

后四态都不产生副作用。这一层零 IO、零网络、纯函数，因为它是安全边界，而安全边界必须能被穷举测试。能被穷举测试的前提是它不依赖外部世界，所以需要外部信息（比如 profile 探测结果）一律作为参数传进去。

`src/chrome.ts` 读盘、`src/policy.ts` 不读盘，这条分工是刻意的。

## 三、四道独立硬闸，取或

```
blocked = spec.risk === "destructive"                    // 动作面构建期固定，模型碰不到
       || judgement.destructive > THRESHOLDS.destructive  // 模型只能加，不能减
       || template.effect === "destroy"                   // 模板自带，抓 sdef 误标

// 第四道只管 Chrome：前三道回答「这件事该不该做」，它回答「在谁的登录态里做」
       || (spec.app === CHROME_APP && profileGate.kind !== "allowed")
```

代码里不存在任何路径让模型的概率**降低**拦截强度。模型的 `destructive` 只能把 safe 的动作抬进 confirm，不能把 destructive 的动作放行。这一条可以被属性测试穷举。

缺省值一律 fail-closed。`PolicyInput.profile` 省略等于「没探测过」，于是 Chrome 动作一律走 confirm。省略等于放行的话，换一个入口接线时忘了传，就成了静默的安全漏洞。

第四道闸放在最后，在置信度检查之后。顺序反过来的话，一个置信度过低的动作会先因为 profile 被问成 confirm，人看到的提示就成了「要不要在某某 profile 下执行」，而真正的问题是模型根本没想清楚。

### 为什么 profile 闸门不能做成「自动切过去」

Chrome 的脚本字典里根本没有 profile 命令，`window` 只有 `mode`（normal / incognito）。「让它用某个 profile」这件事在 AppleScript 侧无解。能做的只有先看清楚要落在哪，陌生就停下来问。

两条路径都要有。只有 CLI 当场问，换一个入口调 loop 就悄悄绕过了整道闸；只有 policy 兜底，用户每次都得先改配置再重跑。

## 四、执行走允许清单，不是风险黑名单

黑名单的失败模式是「没想到的都放行」。动作面是从 sdef 自动生成的，无法预先枚举系统会长出什么命令，所以黑名单在这个架构下是结构性错误。

最典型的例子是 Chrome 的 `execute` 命令（`Execute a piece of javascript`）。在黑名单下它会被判 `safe` 并一路放行到「模型产出的字符串在浏览器里执行」。在允许清单下它根本不进执行注册表，模型即便选中也发不出去。

运行时注册表里只有两条可执行模板：`Google Chrome.make-tab` 与 `Notes.make-note`。

## 五、verify 全部由代码判定

模型不参与自证结果。让模型判断自己刚才做成没有，等于把「做成了」的定义权交给可能出错的那一方。

两类证据都要：脚本自己的返回值（做了什么），以及执行前后各取一次的只读快照差分（世界变了没有）。只有返回值会骗人（返回成功但对象没落地），只有 diff 会误判（别的程序同时也在改）。

实际检查项包括退出码、回读格式前缀、标签页数增量、落点 origin 匹配、笔记数增量、回读笔记实际落在哪个容器、正文含目标 URL。

终止也不信任模型的 `DONE`：

```
done ⟺ 模型选了 DONE ∧ 至少执行过一步 ∧ 每个执行过的步骤 verify.ok === true
```

外加三条不经模型的代码兜底：`LIMITS.maxSteps = 6`、重复守卫（同一动作配同一组解析参数被第二次提议即阻断）、连续 `WAIT` 上限（默认 2 次，超过说明模型在原地打转）。

## 六、中文切片：枚举边界，不猜边界

中文没有空格，`\b` 词边界结构性失效。「搜一下typescript装饰器把链接存进备忘录」里，`把` 是边界还是内容，正则判不了。

`src/spans.ts` 不做分词，做**锚点对枚举**：收集动词触发词、目标触发词、结构词、引号、ASCII 数字连续段的位置，对每个动词锚点的结束位置向后枚举每一个锚点起始位置，产出所有区间。锚点通常 3 到 6 个，候选十来个而非 O(n²) 爆炸，并有数量与长度上限兜底。

边界被穷举之后让模型挑。它只 pick，代码逐字复制，并强制校验选中片段必须是原话的逐字子串，改一个字就拒绝。

## 七、留痕脱敏

journal 默认只落指纹，`src/redact.ts` 按 phase 分派，外部字符串落为 `{len, h}`。

几个刻意的选择：

- **HMAC 而不是裸哈希。** 常见网站和窗口标题的候选集很小，裸哈希可以用彩虹表还原。盐每台机器随机生成一次、只存家目录，跨机器无从反推。
- **未知 phase 落 `default` 分支全量指纹化。** 漏写规则的后果是过度脱敏，不是静默泄露。
- **`redacted` 字段逐条标注，回放时判据是「不等于 `true`」而不是「等于 `false`」。** 留痕是 append-only 的，同一个文件可以跨越一次配置变更。这个字段是后加的，早于它的记录里根本没有这一项，按 `=== false` 判会把那些确实是原文的旧记录静默当成安全的。
- **保留下来没有指纹化的只有结构**：应用名、动作 id、判据名、概率、耗时、通过与否。全抹掉的话留痕就只剩一串无法分辨的哈希，连「哪一步没过」都答不出来。

## 八、AppleScript 的四条硬约束

改脚本模板之前必读 `src/scripts.ts` 的文件头注释，那里记着四类踩过的坑：远程引用 -1700、`container of` 不能链式、没有文档的保留字表、位置定位静默指错对象。

其中两条值得在这里展开。

**保留字表没有文档。** 已经踩中的有 `after`、`at`（`make new … at …` 的参数名）、`st`（序数后缀，如 1st）。踩中只会在真发 Apple Event 的那一刻报 -2741。`test/compile.test.ts` 用 `osacompile` 把这一类提前到 `npm test`。

**按只读 id 定位，永远不按位置。** `window 1` 是层叠顺序而不是「我刚开的那个」，`folder "Notes"` 会撞上同名文件夹，笔记名会重复。这个缺陷类在本项目里出现过四次，包括 live 测试自己的清理代码，那条会关掉用户正在用的页面。
